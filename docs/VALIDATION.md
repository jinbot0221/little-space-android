# Spark 버전 검증 기록

2026-10-22 (한국 시각), 이 클라우드 머신에서 실행했습니다.

| 검사 | 결과 | 범위 |
| --- | --- | --- |
| Android Debug APK·Lint | 통과 | Functions 의존성 없는 Spark 앱 |
| 실제 Firestore Emulator 규칙·경합 테스트 | 37개 통과 / 0개 실패·생략 | 가격·권한·시간·재고·중복·운영·후기·알림·카탈로그 보존 및 회원 유형 |
| Android SDK 통합 테스트 | 6개 통과 / 0개 실패·생략 | Android 8.0 실제 에뮬레이터에서 회원 유형·가입 복구·승인/회수·공간 등록·운영일 추가·선점→확정→취소·알림함 |
| 실제 Spark 프로젝트 배포·과금 | 미실행 | 프로젝트 ID·라이브 설정 미제공, 결제 계정 연결 없음 |

이전의 메모리 트랜잭션 모형 테스트는 제거했습니다. 현재 `firebase/test/rules.test.js`는 **실제 Emulator에 이 저장소의 보안 규칙을 올리고** 승인·거절을 검사합니다. 최대 8시간 16슬롯의 생성·확정·취소가 규칙의 문서 접근·평가 한도 안에서 동작하는지도 검증합니다.

## 중요한 검증 사례

- 두 고객이 같은 슬롯에 경합하면 정확히 1건의 선점만 승인, 인접 구간 허용
- 가격·정원·소유자·명칭·시각 위조, 범위 밖 또는 선택하지 않은 슬롯 변경 거절
- 만료 선점 확정 거절·정리 작업 없는 대체·늦은 해제가 새 선점을 지우지 않음
- 같은 확정 키의 재요청은 예약·알림을 중복 생성하지 않음
- 재고·알림 누락 확정, 환불액 위조 취소, 재고 반환 없는 취소 거절
- 24시간 미만 취소 거절, 타인 거래 접근 거절, 소유 운영자만 차단/해제
- 가짜 서버 시각·권한 상승·알림 스팸·후기 중복·공백 후기 거절
- 기존 운영일 재고는 카탈로그 갱신으로 초기화되지 않음

## 환경과 한계

Firestore Emulator는 **Google 공식 Cloud SDK 1.22.0 배포본**을 공식 manifest의 SHA-256으로 확인한 뒤 원본 JAR의 공식 진입 클래스로 실행했습니다. 테스트 종료 시 실제 Java 프로세스를 정리하도록 실행 PID도 직접 관리합니다. Firebase CLI 기본 JAR 배포 호스트가 403을 반환해 이 공식 배포 경로를 사용했습니다. JAR manifest 변경, 체크섬 변경, TLS 검증 해제는 하지 않았습니다.

Auth Emulator도 실제 실행했고, Android 테스트는 mock 인증 세션이 아닌 이메일 로그인으로 검사했습니다. 규칙 공격 테스트는 Rules Unit Testing의 인증 컨텍스트와 관리자 초기화 데이터를 사용합니다. 운영 보안 설정, 실제 계정 메일 발송, 대규모 부하, 실제 Spark 일일 할당량 소진, 라이브 데이터 마이그레이션은 검사하지 않았습니다.

이전 Functions 버전과 화면 촬영 기록은 [과거 검증 기록](VALIDATION-legacy.md)에 보존했습니다. 스크린샷은 촬영용 가상 데이터이며 현재 Spark 서버 검증의 증거로 사용하지 않습니다. 회원가입 화면은 회원 유형 선택을 포함해 2026-10-22에 다시 촬영했고 나머지 화면은 이전 버전입니다.

`./scripts/install-cloud.sh` 최종 재실행도 성공했습니다. lockfile 설치, Debug APK·Lint, 공식 Emulator 실행, 30개 규칙 테스트, 자신이 시작한 Emulator 종료까지 확인했습니다. 설치·시작 지침은 Spark 구성으로 환경 설정 초안에 저장했으며 초안 저장은 게시를 의미하지 않습니다.

## 회원 유형 변경 검증

- 일반 이용자·장소 제공자 가입, Auth 로그아웃/재로그인 후 Firestore 유형 복구와 유형별 초기 홈을 Android SDK로 확인했습니다.
- 제공자 신청자는 `approved:false`로 저장되며, 소유 공간이 있어도 승인 없이 운영 차단을 저장할 수 없습니다.
- 관리자 승인된 제공자는 운영 홈과 본인 공간 3곳을 확인하고, 로그아웃하면 일반 탐색 화면으로 돌아갑니다.
- Firestore 연결을 앱 프로세스에서 한 번만 설정해 화면 재생성/Repository 재생성 시 `useEmulator()` 예외가 발생하지 않도록 수정했습니다.
- 선택적 관리 도구 `approve-host.js`는 구문 검사만 했으며 라이브 계정 승인이나 보안 규칙 배포는 실행하지 않았습니다.

## 앱 시작·로그인 권한 오류 보완

본인 프로필(기존 계정·아직 없는 문서) 조회와 공개 공간 조건 조회가 현재 규칙에서 허용됨을 실제 Firestore Emulator로 확인했습니다. 앱에서는 회원정보/공간 조회 거절을 별도로 표시하며 가입 정보가 없는 Auth 계정은 앱 재실행 시 가입 완료 화면으로 연결합니다. Android 에뮬레이터에서 미완료 계정 복구를 포함한 4개 테스트가 통과했습니다. 이 환경의 Firebase CLI 로그인 계정은 없으므로 라이브 프로젝트의 규칙 상태 확인·배포는 하지 않았습니다.

## Firestore 콘솔 승인으로 전환

운영 권한을 Auth custom claim 대신 `users/{UID}`의 `accountType:host`·boolean `approved:true`·약관 동의로 확인하도록 변경했습니다. 이전 custom claim 방식 안내는 [현재 콘솔 승인 절차](SPARK.md#firebase-콘솔에서-장소-제공자-승인)로 대체합니다. 신규 가입은 `approved:false`, 기존 필드 없는 제공자는 승인 대기입니다.

- 실제 Firestore Emulator에서 자기 승인 생성/변경/회수, 다른 제공자의 공간 운영·예약 조회가 거절됨을 확인했습니다.
- 관리자 승인 전 거절 → 승인 후 본인 공간 운영/예약 조회 허용 → 회수 후 거절을 같은 인증 세션으로 검사했습니다. `host:true` claim만 가진 계정도 미승인이면 거절합니다.
- Android SDK에서 에뮬레이터 관리자 REST 요청으로 콘솔 승인/회수를 재현하고, 로그아웃 없이 승인 상태 새로고침으로 미승인→승인→미승인이 반영됨을 확인했습니다. 에뮬레이터 관리자 토큰은 androidTest에만 있으며 배포 앱에는 없습니다.
- 일반 이용자와 제공자별 가입·초기 홈·로그인 복구, 승인된 제공자의 본인 공간 조회, 미완료 가입 복구, 예약·취소를 포함해 Android 테스트 5개가 통과했습니다. APK·Lint도 통과했습니다.
- 실제 `littlespace-a7087`의 규칙 배포·회원 승인은 실행하지 않았습니다. 최신 규칙 게시와 새 앱 설치가 모두 필요합니다.

## 제공자 공간 등록·인덱스 안내

- 승인된 제공자가 본인 소유의 유효한 v2 공간과 최대 30일 운영일을 원자적으로 생성할 수 있음을 실제 Firestore Emulator로 검사했습니다.
- 미승인/타인 소유 등록, 가격·정원·운영 시간·이미지 URL·시설 위조, 잘못된 KST 날짜/범위/빈 슬롯 초기화, 기존 재고 재초기화는 거절합니다.
- Android SDK에서 공간 등록→동일 등록 재시도→고객 공개 조회→선점·확정→제공자 운영일 추가→기존 예약 유지→고객 취소를 검증했습니다. 누락된 운영일만 추가되며 같은 요청의 재시도는 0일 추가로 끝납니다.
- 규칙 테스트 37개와 Android 테스트 6개가 통과했고 APK·Lint도 통과했습니다.
- 공간 공개 조회 인덱스를 추가하고 모든 앱 복합 조회를 `firestore.indexes.json` 및 운영 안내에 대응시켰습니다. 앱은 인덱스 관련 FAILED_PRECONDITION을 한국어로 안내합니다. 라이브 인덱스 배포/생성 완료는 확인하지 않았으며 Emulator 테스트는 인덱스 필요 조건을 강제하지 않습니다.

신규 공간 등록 화면은 2026-10-22에 debug 오프라인 촬영용 상태로 전체 화면 캡처하여 `docs/screenshots/15-space-register.png`에 추가했습니다. 실제 등록 동작의 증거는 별도의 Android SDK 통합 테스트입니다.
